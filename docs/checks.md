# チェック仕様（設計案）

この文書は実装前の要件を整理するものです。記載したCLI、判定、終了コードはまだ実装されていません。

## 共通の実行方針

- 主用途は会場設営時に各所を回って行う開通確認とし、初期版はmacOS・Linuxの両方を対応対象とする。OSバージョン・ディストリビューションごとの対応範囲は実装時に検証する。
- プロファイル未指定時は、本書の診断項目をすべて実行し、結果を画面に表示して終了する。ファイルや保存先ディレクトリは作成しない。
- `--profile <path>` でプロファイルを明示した場合は、指定された検査項目と保存設定を適用する。プロファイルを自動探索・自動読込しない。
- 既定ではIPv4・IPv6の両方を対象とし、各チェックの通信経路を固定する。
- `--ipv4-only` / `--ipv6-only` で明示的に対象を絞れるようにする。両方を同時指定した場合は入力エラーにする。
- 接続先、DNS問い合わせ名、HTTPSのURL、タイムアウト、回数、パケットサイズは変更可能にする。
- 各チェックに期限を設け、すべての試行を含む実行全体にも上限を設ける。
- 小さいパケットでの疎通と大きいパケットでの疎通を比較する。
- チェックに失敗しても、実行できる残りの項目は続行する。
- 通常の接続状態チェックで設定を変更しない。SSIDやMACアドレスの収集は初期仕様に含めない。

## 検査プロファイル

初期形式はJSONとし、設定のスキーマバージョンを `schema_version: 1` で指定する。詳細なJSON Schemaと各検査の既定値は実装時に定義するが、次の規則を初期仕様とする。

| 設定 | 意味・省略時の扱い |
| --- | --- |
| `schema_version` | 必須。未対応バージョンは入力エラー |
| `name` | 任意のプロファイル名。指定時は画面・ログ・JSON結果に含める |
| `checks` | 必須。実行する検査IDの空でない配列。省略による全項目実行はしない |
| `ip_versions` | 対象のIPバージョン。省略時は `[4, 6]`。指定する場合は4・6の空でない配列 |
| `ping.targets` | `icmp` の宛先IPアドレスの配列。省略時は標準のIPv4・IPv6宛先。指定時は既定一覧を置き換える |
| `ping.count` | `icmp` の宛先ごとの送信回数。省略時は `5`。正の整数で指定 |
| `dns.servers` | 直接問い合わせするDNSサーバーのIPアドレスの配列。省略時は標準のIPv4・IPv6サーバー。指定時は既定一覧を置き換える |
| 接続先・検査条件 | DNS問い合わせ名、HTTPS URL、パケットサイズ、タイムアウト、回数などを変更可能にする。キーと既定値の詳細は実装時に定義 |
| `output.text_log` | テキストログを保存するか。省略時は `false` |
| `output.directory` | 保存先。保存が有効な場合の省略値は `results`。相対パスは実行時の作業ディレクトリを基準にする |

選択可能な検査IDは `connection`、`icmp`、`dns_udp`、`dns_tcp`、`system_dns`、`mtu`、`https`、`traceroute` とする。`dns_udp` と `dns_tcp` は、それぞれ選択した通信経路でA・AAAAの両方を問い合わせる。`system_dns` の実際の通信経路はIPバージョン指定で固定できるとみなさない。

- 読めないファイル、不正なJSON、未知のキー・検査ID、重複した検査ID・IPバージョン、不正な型・値は入力エラーとし、通信を始めず終了コード `2` で終了する。全項目実行へ暗黙に切り替えない。
- 適用順は組み込み既定値、指定プロファイル、明示したCLIオプションの順とする。CLI内で矛盾した指定は入力エラーにする。
- プロファイル未指定時も、`--ipv4-only` / `--ipv6-only` は対象の通信経路を絞る。検査項目自体は全項目のままとする。
- 未選択の検査項目は対象外として扱い、依存コマンドの不足確認や総合判定に含めない。
- 検査の内部処理と選択項目を区別する。例えば `https` には接続先の名前解決が必要であり、`mtu` には比較用の小さいパケットの疎通確認が必要となる。これらの前提処理は実行するが、未選択の検査一式を暗黙に追加しない。
- 選択項目を実行できなかった場合は、未選択の場合と区別して `SKIP` と理由を記録する。
- `ping.targets` と `dns.servers` は独立して設定する。各配列は空にできず、IPリテラルで指定し、不正なアドレスと同一IPの重複を入力エラーとする。ホスト名の解決による宛先変更は行わない。
- 各一覧から対象IPバージョンのアドレスを選ぶ。対象外のIPバージョンの宛先は送信対象に含めず、対象外と表示する。該当する検査を選択しているのに、選択したIPバージョンの宛先が1件もない場合は入力エラーとし、既定宛先を補わない。
- 宛先数、送信回数、DNS試行回数、同時実行数、送信頻度に上限を設け、上限を超える設定は診断前に入力エラーとする。上限値・送信間隔の詳細は実装時に定義する。
- 実際のプロファイルは `local/` または `*.local.*` に置く。リポジトリ内の設定例にはダミー値を使う。

## 画面表示とテキストログ

- 画面表示は常に行い、既定では人向けの日本語テキストとする。`--format json` は標準出力をJSONにする指定であり、ファイル保存を有効にしない。
- プロファイルの `output.text_log` が `true` の場合だけ、UTF-8のテキストログ（`.log`）を保存する。JSON画面出力との併用時も、保存するログは人向けのテキストとする。
- 保存するログには、実行日時、適用プロファイルと検査条件、各検査の対象・IPバージョン・経過時間・判定・理由、総合判定を含める。取得できない値は理由を添える。
- pingは各宛先の各試行と集計、DNSは各サーバー・通信経路・レコード種別・転送方式ごとの結果を、画面・JSON・有効時のテキストログに含める。「記録」はこれらの診断結果への格納を指し、保存設定のない実行でファイルは作らない。
- 保存先は `results/` または `reports/` 配下を基本とする。保存時だけ必要なディレクトリを作り、実行日時と衝突を防ぐ識別子で実行ごとに別ファイルを作る。既存ファイルを上書きしない。
- 保存先と書込権限は診断前に確認し、準備に失敗したら理由を表示して終了コード `2` で終了する。実行中の書込失敗も明示して終了コード `2` とし、可能な限り残りの診断と画面表示は続ける。
- 入力不正や依存確認で診断前に中断した場合は、診断結果ファイルを作らない。
- `output` の省略時、`text_log: false`、プロファイル未指定時は、ファイル保存も保存先ディレクトリの作成も行わない。
- HTTP応答本文、Cookie、認証ヘッダーは保存しない。ログには会場や端末の情報が含まれ得るため公開しない。

## 依存コマンド不足時の動作

診断前に、選択項目の実行に必要な外部コマンドだけを確認する。`traceroute` などが不足していた場合は、不足一覧、影響する検査、OS・ディストリビューションに合ったインストール方法を表示する。環境を判別できない場合は、一律のインストールコマンドを決め打ちせず、確認すべきツールと導入手順の確認先を案内する。ツールを本CLI内から自動インストールしたり、管理者権限へ自動昇格したりしない。

端末で対話可能な場合は、不足項目をまとめて提示して次の二択を尋ねる。

| 選択 | 動作 |
| --- | --- |
| 続行 | 不足コマンドが必要な項目を `SKIP`（理由: 依存コマンド不足）として記録し、他の検査を実行する。全体成功にしない |
| 中断 | ネットワーク診断を開始せず終了コード `2` で終了する |

- 空入力の既定は中断とし、入力終了（EOF）でも中断する。
- 対話できない場合は入力待ちに入らず、既定で不足理由を表示して終了コード `2` で中断する。
- 自動実行向けに `--on-missing skip` / `--on-missing abort` を用意し、指定時は対話せず選択した方針を適用する。不足がなければそのまま診断する。
- 案内と対話は標準エラー出力を使用し、JSONの標準出力へ混ぜない。診断開始前に中断した場合も、JSONモードでは機械可読な起動エラーを返す。
- 権限不足や未対応の機能は依存コマンド不足と区別し、インストールを勧めて解決した扱いにしない。実行時にコマンドが利用不能になった場合も理由を記録し、他の検査を続ける。

## 診断項目

| 項目 | IPv4 | IPv6 | 記録する情報 |
| --- | --- | --- | --- |
| 接続状態 | アドレス、デフォルトルート | アドレス、デフォルトルート | 対象インターフェース、経路の有無 |
| ICMP Echo | 複数指定可。既定は `1.1.1.1` | 複数指定可。既定は `2606:4700:4700::1111` | 各宛先に既定5回。各試行の結果、送信・応答数、RTT、ロス、エラー |
| DNS UDP | 指定した全IPv4サーバーのUDP/53 | 指定した全IPv6サーバーのUDP/53 | サーバーごとの問い合わせ名、種別、応答コード、応答時間 |
| DNS TCP | 指定した全IPv4サーバーのTCP/53 | 指定した全IPv6サーバーのTCP/53 | サーバーごとの問い合わせ名、種別、応答コード、応答時間 |
| OSのDNS | OSリゾルバーによる名前解決 | OSリゾルバーによる名前解決 | A/AAAAの応答と指定DNSとの差異 |
| 大きなICMPパケット | DFを指定 | 送信元での断片化を禁止 | 要求サイズ、実際の送信条件、応答・エラー |
| HTTPS | IPv4に固定 | IPv6に固定 | TCP接続、TLS検証、HTTPステータス、応答時間 |
| traceroute | IPv4に固定 | IPv6に固定 | 宛先、応答したホップ、各応答時間、宛先到達の有無、実行条件 |

OSのDNS確認では、A/AAAAレコードが得られたことからDNS通信自体のIPv4/IPv6を推定しません。OSリゾルバーの実際の通信経路が取得できない場合は「OS設定経由・通信経路不明」と表示します。

### ICMP Echo（ping）

- `ping.targets` に指定した全宛先を対象にする。プロファイル未指定時や一覧の省略時は、標準のIPv4・IPv6宛先を使用する。対象IPバージョンの選択は共通規則に従う。
- 既定では **各宛先に5回** ICMP Echoを送信する。全宛先を合わせて5回ではない。`ping.count` で変更可能にし、応答の有無にかかわらず通常は設定回数の試行を行う。
- 一部宛先の失敗や無応答で残りの宛先を打ち切らない。一括診断として設定回数で終了し、常時監視は初期仕様に含めない。
- 宛先ごとに、予定回数、実送信数、応答数、ロス率、各試行の番号・RTTまたはタイムアウトなどの理由、応答RTTの最小・平均・最大、検査の経過時間を記録する。RTTを取得できなければ未取得の理由を示し、値を補わない。
- 全体期限や実行不能により5回を完了できなかった場合は、実際の試行数と打切り理由を示す。未送信の試行をパケットロスに数えず、未実行分は `SKIP` として未確認であることを残す。全く送信できなかった宛先のロス率は算出しない。
- ロスは必ず結果に残し、部分的なロスの注意判定は共通の閾値設定に従う。全試行が無応答の場合は原則 `FAIL` とし、同じ通信経路でDNS・HTTPSが成功している場合は共通の判定規則に従い `WARN` とする。別のping宛先の成功だけでは無応答宛先の判定を成功にしない。
- この送信回数・宛先一覧は通常の `icmp` 検査に適用する。大きなパケットとtracerouteはそれぞれの検査条件を使い、複数ping宛先へ暗黙に展開しない。

### DNS

`dns.servers` に指定した全DNSサーバーへ直接問い合わせます。既定は `1.1.1.1` と `2606:4700:4700::1111` です。DNSサーバーへのpingやTCP接続だけで成功とせず、実際のDNSクエリと応答を検証します。

通信経路、レコード種別、転送方式を分けます。両方式を選択し、IPv4・IPv6各1台を対象とした場合は次の8通りとなり、サーバーを追加した場合も各サーバーで同じ検査を行います。

| DNSサーバーへの通信経路 | 問い合わせるレコード | 転送方式 |
| --- | --- | --- |
| IPv4 | A | UDP、TCP |
| IPv4 | AAAA | UDP、TCP |
| IPv6 | A | UDP、TCP |
| IPv6 | AAAA | UDP、TCP |

AAAAの応答が得られてもIPv6通信ができたことにはなりません。IPv6のDNSサーバーへAを問い合わせる場合もあります。

- 各サーバーのIPアドレスに対応する通信経路を固定し、選択した `dns_udp` / `dns_tcp` それぞれでA・AAAAを問い合わせる。両方式を選択した場合はサーバー1台あたり4通りで、pingの送信回数5回はDNSに適用しない。
- あるサーバーの失敗後も残りのサーバーを検査する。「いずれか1台が応答すれば成功」という扱いにはせず、各サーバーの失敗を個別結果と総合判定に残す。
- サーバーIP、通信経路、問い合わせ名、レコード種別、転送方式、試行数、応答コード、取得レコード、応答時間、判定・理由を記録する。異なるサーバーの応答内容が違うだけで直ちに異常とは判定しない。
- 問い合わせ名には、A・AAAAの両方が期待できる公開ドメインを選び、実装時に動作を確認する。現時点では既定名を未決定とする。
- `NOERROR` だけで成功にしない。必要なレコードを得られたかも確認する。
- UDP応答のTCフラグ（切り詰め）を記録する。TCPへの再試行結果はUDPの結果と分ける。
- UDPが失敗しTCPが成功した場合も、UDPの問題を結果に残す。
- タイムアウト、`NXDOMAIN`、`SERVFAIL`、応答の欠落を区別する。
- DNSSEC、EDNSの応答サイズ、DoH/DoTは後続の拡張候補とする。

### 大きなパケット・MTU

`--packet-size` は **IPヘッダーを含むIPパケット全体のバイト数** とします。EthernetやWi-Fiのフレーム全体のサイズではありません。

| IPパケットサイズ | IPv4 ICMPペイロード | IPv6 ICMPペイロード |
| --- | --- | --- |
| 1280バイト | 1252バイト | 1232バイト |
| 1500バイト | 1472バイト | 1452バイト |

上表はIPv4ヘッダー20バイト／IPv6ヘッダー40バイト、ICMPヘッダー8バイトで、IPオプション・拡張ヘッダーを含まない場合の計算です。

IPヘッダーと断片化の扱いは [IPv4仕様（RFC 791）](https://www.rfc-editor.org/rfc/rfc791.html) と [IPv6仕様（RFC 8200）](https://www.rfc-editor.org/rfc/rfc8200.html)、ICMPv6 Echoの形式は [RFC 4443](https://www.rfc-editor.org/rfc/rfc4443.html#section-4.1) を参照します。

- IPv4ではDFを指定し、途中の断片化で大きなパケットが通ったように見えることを防ぐ。
- IPv6ではルーターによる断片化は行われないが、送信元での断片化は起こり得る。利用するOS・コマンドで送信元の断片化も禁止できることを確認する。
- 条件を満たせないOSや権限では `SKIP` と理由を表示し、MTUチェックが成功した扱いにしない。
- 小さいパケットで疎通が得られなければ、大きいパケットの失敗だけからMTU問題とは断定しない。
- ローカルインターフェースのMTU制限、ICMPの応答拒否、経路上の制限、タイムアウトを分けて表示する。
- 1500バイトが通らないこと自体は、ネットワーク全体の故障を意味しない。トンネルなどでMTUが小さい環境もある。
- 指定サイズの試験は、そのサイズでの通過確認とする。経路MTUの上限探索やPMTUDブラックホールの確定診断は後続の機能とする。
- 想定するMTUを運用側が必須条件として指定した場合は、その条件に基づいて判定する。

### HTTPSと利用可否

- IPv4・IPv6の通信経路を固定し、指定URLへのTCP/443、TLS、HTTPの段階を記録する。
- 証明書検証を有効にし、ホスト名とSNIを正しく扱う。
- 宛先のURLと期待するHTTPステータス・応答は実装時に決める。任意のHTTP応答を一律に成功にしない。
- リダイレクトは検出して表示し、回数と接続先に制限を設ける。
- 想定外の応答はキャプティブポータルの可能性を示せるが、原因の確定には追加確認が必要とする。
- 応答本文、Cookie、認証ヘッダーは通常の結果に保存しない。
- HTTPSの失敗にはDNSの失敗が関係する場合があるため、理由と前段の結果を併記する。

### traceroute

- 既定の宛先は標準のIPv4・IPv6宛先とし、変更可能にする。`ping.targets` の変更ではtracerouteの宛先を変更しない。逆引きを抑止し、ホップ数、ホップごとの試行回数、待ち時間、送信頻度、検査全体の実行時間に上限を設ける。数値とプローブ方式はOS差異を確認して実装時に定義する。
- macOSとLinuxのコマンド・オプション、IPv6の実行方法、権限、終了コード、出力形式の違いはOS別の処理へ分離する。コマンド名だけで必要な機能を利用可能と判定しない。
- 宛先まで応答が得られた場合は `PASS`。無応答ホップや上限内の未到達は情報を残して `WARN` とし、それだけで利用不可や障害箇所を確定しない。コマンド利用不能は理由に応じて `SKIP`、解析不能などの内部エラーは `ERROR` とする。
- 途中のホップが応答しないことから、その先の通信が止まっていると推定しない。DNS・HTTPSなどの結果と併せて判断する。

## 結果の判定

| 判定 | 意味 |
| --- | --- |
| `PASS` | そのチェックの成功条件を満たした |
| `WARN` | 実行できたが注意が必要。例: ICMP無応答だが同一通信経路のHTTPSは成功、任意サイズの通過失敗 |
| `FAIL` | 必須の通信条件を満たさなかった。例: 指定DNSの名前解決失敗、HTTPSの失敗 |
| `SKIP` | 対象外、依存不足、権限不足、未対応などで実行しなかった |
| `ERROR` | 入力不正や内部エラーで信頼できる結果を得られなかった |

既定ではIPv4・IPv6両方を必須対象とし、片系の経路がない場合も結果に残します。片系のみの運用ではプロファイルまたはCLIで対象を明示的に絞ります。対象外の項目は総合判定に含めません。選択された検査は実行完了を必須とし、依存コマンド不足などで `SKIP` になった場合は「未確認」を表示し、全体成功にしません。各検査の成功条件は個別仕様に従い、任意サイズの通過失敗やtracerouteの未到達などは `WARN` とします。

複数宛先を指定した検査は宛先ごとに判定し、成功した宛先で他の宛先の `WARN` / `FAIL` / `ERROR` / 未確認を隠しません。全体期限で未実行となった宛先・DNS問い合わせも `SKIP` として明示し、全件確認済みとはしません。

ping無応答の場合、同じ通信経路でDNS・HTTPSが成功していれば `WARN` として扱います。複数の結果が失敗しても原因をICMPの結果だけから確定しません。RTT・ロスの注意閾値は設定可能とし、既定値は実測後に決めます。

総合表示では「設定された検査条件を満たしたか」を示し、インターネット全体や無線品質の保証として扱いません。

### 終了コード案

| 終了コード | 意味 |
| --- | --- |
| `0` | 対象のチェックを完了し、`WARN` / `FAIL` / `ERROR` および必須項目の `SKIP` がない |
| `1` | チェックを完了したが、`WARN` / `FAIL` または必須項目の `SKIP` がある |
| `2` | 入力不正、起動不可、依存コマンド不足時の中断、ログ保存失敗、内部エラーなどで指定条件の診断・保存を完了できなかった |

複数の状態がある場合は `2`、`1`、`0` の順で優先します。JSONにはスキーマバージョン、実行日時、適用プロファイル、選択された検査項目と対象条件、各項目の判定・理由・経過時間、総合判定を含めます。詳細なJSONスキーマは実装時に定義します。

## 初期実装の対象外

大量トラフィックによる帯域測定、負荷試験、ポートスキャン、Wi-Fiのローミング・電波測定、APやルーターの設定変更は初期実装に含めません。必要に応じて後から明示的な機能として検討します。
